Proyectos de Ejemplo: Casos Reales Desarrollados

A continuación se presentan dos proyectos reales desarrollados por los alumnos de la materia, que sirven como caso de estudio para aplicar los conceptos de calidad de software.

🦷 Sistema "Sonrisa Sana" - Consultorio Odontológico

📊 Ficha del proyecto:
• Cliente: Dra. Laura Méndez, consultorio dental particular
• Problema detectado: Mala organización manual de citas, pérdida de historiales clínicos, dificultad para hacer seguimiento de tratamientos, falta de control financiero
• Metodología: Scrum (sprints semanales)
• Tecnologías: PHP, MySQL, Bootstrap, JavaScript, Chart.js, Dompdf
• Duración: 5 semanas (1 sprint por semana)
• Equipo: 2 desarrolladores, 1 tester
• Costo final: $21,000 MXN (pago único)

📋 Funcionalidades implementadas:

👥 Gestión de pacientes

  • Registro de pacientes con datos personales
  • Historial clínico digital
  • Buscador en tiempo real
  • Edición y eliminación de registros
  • Subida de radiografías y documentos

📅 Gestión de citas

  • Calendario interactivo (semanal/mensual)
  • Bloqueo de horarios no disponibles
  • Recordatorios automáticos por email
  • Reagendación y cancelación
  • Historial de citas por paciente

💊 Gestión de tratamientos

  • Catálogo de tratamientos predefinidos
  • Asignación de tratamientos a pacientes
  • Seguimiento de evolución
  • Escala de dolor (1-10)
  • Fotografías de evolución

💰 Módulo financiero

  • Registro de pagos y abonos
  • Generación de facturas (PDF)
  • Reporte de ingresos mensuales
  • Gráficos de evolución financiera
  • Estado de cuenta por paciente

📊 Entregas por sprint (Scrum):

SprintEntregableHistorias de usuario completadas
Sprint 1Base de datos + Requerimientos"Como secretaria quiero registrar pacientes", "Como dentista quiero ver listado de pacientes"
Sprint 2Maquetado HTML + Estructura base"Como secretaria quiero navegar por el sistema", "Como dentista quiero ver dashboard"
Sprint 3Estilos CSS + Bootstrap + Buscador"Como secretaria quiero buscar pacientes", "Como usuario quiero interfaz responsiva"
Sprint 4Controladores PHP + Conexión BD + Seguridad"Como secretaria quiero agendar citas", "Como dentista quiero registrar tratamientos"
Sprint 5Módulo de pagos + Facturas + Gráficos"Como dentista quiero generar facturas", "Como dentista quiero ver reportes financieros"

📊 Principales dificultades y soluciones:

  • Dificultad: El cliente solicitó módulo de pagos a mitad del desarrollo → Solución: Scrum permitió agregar nuevas historias en sprints posteriores sin afectar entregas anteriores
  • Dificultad: Problemas de rendimiento en el buscador de pacientes → Solución: Optimización de consultas SQL y adición de índices
  • Dificultad: Conflictos de horarios en citas → Solución: Validación en tiempo real y bloqueo automático de horarios ocupados
  • Dificultad: El cliente no sabía exactamente qué reportes necesitaba → Solución: Reuniones semanales de revisión de sprint para ajustar prioridades
📌 Lección principal del proyecto dental:
"Scrum permitió adaptarse a cambios solicitados por el cliente durante el desarrollo. Si hubiéramos usado Cascada, el módulo de pagos habría sido difícil de agregar sin rehacer partes del sistema."

🧠 Sistema para Consultorio de Psicología

📊 Ficha del proyecto:
• Cliente: Lic. Carlos Rodríguez, psicólogo clínico
• Problema detectado: Información de pacientes en papel, duplicidad de registros, errores en agenda, falta de control de consultas, dificultad para acceder a historiales antiguos
• Metodología: Cascada (fases secuenciales)
• Tecnologías: Java, MySQL, Swing (interfaz gráfica)
• Duración: 5 semanas
• Equipo: 2 desarrolladores, 1 tester
• Costo final: $11,000 MXN (pago único)

📋 Funcionalidades implementadas:

🔐 Seguridad y autenticación

  • Login con roles (secretaria/psicólogo)
  • Contraseñas encriptadas (SHA-256)
  • Bitácora de accesos
  • Cierre de sesión automático por inactividad

👥 Gestión de pacientes

  • Alta, baja y modificación de pacientes
  • Búsqueda por nombre, teléfono o correo
  • Ficha psicológica básica
  • Historial de consultas

📅 Agenda de citas

  • Vista semanal de horarios
  • Validación de horarios (evita doble reserva)
  • Bloqueo de horas de comida/descanso
  • Recordatorios visuales

📝 Registro de consultas

  • Notas de sesión (diagnóstico, observaciones)
  • Escalas de evaluación (ansiedad, depresión)
  • Recomendaciones y tareas para el paciente
  • Historial cronológico

📊 Fases ejecutadas (Cascada):

FaseEntregableDuraciónValidación del cliente
Fase 1Análisis y requerimientos1 semanaDocumento SRS aprobado
Fase 2Diseño de base de datos e interfaces1 semanaModelo ER y mockups aprobados
Fase 3Programación de módulos2 semanasDemo funcional aprobada
Fase 4Pruebas funcionales y validación3 díasSin bugs críticos
Fase 5Implementación y entrega2 díasCapacitación y firma de aceptación

📊 Principales dificultades y soluciones:

  • Dificultad: El cliente no tenía claros todos los requisitos al inicio → Solución: Se invirtió más tiempo en la fase de análisis (1 semana adicional) para garantizar que el SRS fuera completo
  • Dificultad: Problemas de rendimiento en Java Swing con muchos registros → Solución: Implementación de paginación y carga diferida (lazy loading)
  • Dificultad: El cliente solicitó un cambio después de iniciada la fase 3 → Solución: Se evaluó el impacto y se acordó posponer el cambio para una versión futura (evitó retrabajo)
  • Dificultad: Integración de la base de datos MySQL con Java Swing → Solución: Uso de JDBC con pool de conexiones
📌 Lección principal del proyecto psicología:
"Cascada fue adecuada porque los requisitos eran estables y el cliente los tenía claros. La documentación detallada permitió que el cliente entendiera exactamente qué iba a recibir antes de comenzar el desarrollo."

📌 Conclusión de la comparativa:

📚 Lecciones aprendidas de ambos proyectos

✅ Lo que funcionó bien

  • Reuniones semanales con el cliente para revisar avances
  • Documentación clara de requisitos (SRS)
  • Pruebas continuas durante el desarrollo
  • Uso de control de versiones (Git) desde el día 1
  • Márgenes de contingencia en costos (15%)
  • Capacitación al cliente al final del proyecto

⚠️ Lo que se podría mejorar

  • Más pruebas automatizadas (solo se hicieron manuales)
  • Mejor estimación inicial de esfuerzo (hubo desviaciones del 10-15%)
  • Documentación más detallada de la API (para el proyecto web)
  • Más tiempo para pruebas de usabilidad
  • Implementar un entorno de pruebas separado de desarrollo

💡 Recomendaciones para futuros proyectos

  • Involucrar a QA desde la fase de requisitos
  • Realizar pruebas de carga antes del despliegue
  • Usar herramientas de automatización para regresión
  • Establecer métricas de calidad desde el inicio
  • Realizar retrospectivas al final de cada sprint/fase
  • Documentar lecciones aprendidas para proyectos futuros
📌 Top 10 lecciones aprendidas:

1. 📋 La fase de requisitos es la más crítica (invertir tiempo aquí ahorra costos después)
2. 🔄 Scrum es ideal cuando los requisitos pueden cambiar; Cascada cuando son estables
3. 🧪 Las pruebas continuas reducen los defectos en producción
4. 💬 La comunicación semanal con el cliente evita malentendidos
5. 📝 La documentación clara facilita el mantenimiento futuro
6. 🔧 El control de versiones es obligatorio incluso en equipos pequeños
7. 💰 Siempre incluir un margen de contingencia (15-20%) en presupuestos
8. 👥 La capacitación al cliente mejora la adopción del sistema
9. 📊 Las métricas ayudan a medir y mejorar la calidad
10. 🎯 Elegir la tecnología adecuada (web vs escritorio) según necesidades del cliente
