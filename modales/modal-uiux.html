🎨 ¿Qué es la usabilidad?

La usabilidad es la facilidad con que los usuarios pueden usar el software para lograr sus objetivos de manera efectiva, eficiente y satisfactoria.

📌 Los 5 atributos de la usabilidad (Jakob Nielsen):

1. 📚 Aprendizaje (Learnability): ¿Qué tan fácil es realizar tareas básicas la primera vez?
2. ⚡ Eficiencia (Efficiency): ¿Qué tan rápido pueden realizar las tareas los usuarios experimentados?
3. 🔄 Memorabilidad (Memorability): ¿Pueden los usuarios reanudar el uso después de un tiempo sin tener que volver a aprender?
4. ❌ Errores (Errors): ¿Cuántos errores cometen los usuarios? ¿Qué tan graves son? ¿Pueden recuperarse fácilmente?
5. 😊 Satisfacción (Satisfaction): ¿Qué tan agradable es usar el sistema?

📌 Principios de diseño de usabilidad:

Visibilidad del estado del sistema

El sistema debe mantener informado al usuario sobre lo que está ocurriendo.

Ejemplo: Barra de progreso, indicador de carga.

Correspondencia con el mundo real

Usar un lenguaje y conceptos familiares para el usuario.

Ejemplo: Icono de carrito de compras, papelera de reciclaje.

Control y libertad del usuario

Ofrecer "salidas de emergencia" para deshacer acciones.

Ejemplo: Botón "Deshacer", "Cancelar", "Atrás".

Consistencia y estándares

Mantener la misma convención en todo el sistema.

Ejemplo: Mismo color para botones de acción, misma ubicación del menú.

Prevención de errores

Mejor prevenir errores que mostrar mensajes de error.

Ejemplo: Deshabilitar botón "Enviar" hasta que el formulario sea válido.

Reconocimiento antes que recuerdo

Minimizar la carga de memoria del usuario.

Ejemplo: Menús visibles, autocompletado, historial.

✅ Beneficios de una buena usabilidad:
• Aumenta la satisfacción del usuario
• Reduce los costos de soporte técnico
• Aumenta la productividad de los usuarios
• Reduce la tasa de abandono del producto
• Aumenta las conversiones (en comercio electrónico)
• Mejora la percepción de la marca

📊 Escala SUS (System Usability Scale) - Explicación detallada:

📝 SUS es un cuestionario de 10 preguntas con respuestas del 1 al 5:
1 = Totalmente en desacuerdo
3 = Neutral
5 = Totalmente de acuerdo

Preguntas (alternan positivas y negativas):
1. Pienso que me gustaría usar este sistema frecuentemente.
2. Encontré el sistema innecesariamente complejo.
3. Pensé que el sistema era fácil de usar.
4. Creo que necesitaría el apoyo de un técnico para usar este sistema.
5. Encontré las funciones del sistema bien integradas.
6. Pensé que había mucha inconsistencia en el sistema.
7. Imagino que la mayoría aprendería a usar el sistema rápidamente.
8. Encontré el sistema muy difícil de usar.
9. Me sentí muy confiado usando el sistema.
10. Necesité aprender muchas cosas antes de poder usar el sistema.

Cálculo de la puntuación SUS:
• Preguntas impares (1,3,5,7,9): (respuesta - 1)
• Preguntas pares (2,4,6,8,10): (5 - respuesta)
• Sumar todas las puntuaciones y multiplicar por 2.5
• Resultado: 0-100

📊 Interpretación de la puntuación SUS:

Puntuación SUS        Calificación
─────────────────────────────────────
100-90               🌟 Excelente (Mejor que el 99%)
89-80                👍 Bueno (Mejor que el 90%)
79-70                📊 Aceptable (Promedio)
69-60                ⚠️ Por debajo del promedio (Necesita mejora)
59-0                 ❌ Malo (Requiere rediseño urgente)
📌 Curiosidad:
• La puntuación SUS promedio de la industria es 68
• Apps bancarias suelen tener 75-85
• Apps de entretenimiento (Netflix, Spotify) tienen 85-95
• Sistemas empresariales internos suelen tener 50-65

♿ Accesibilidad (WCAG 2.1)

La accesibilidad garantiza que las personas con discapacidades puedan usar el software de manera efectiva.

📌 Principios WCAG 2.1 (POUR):

Perceivable (Perceptible): La información debe ser presentada de forma que todos los usuarios puedan percibirla.
  → Ejemplo: Texto alternativo para imágenes, subtítulos para videos.

Operable (Operable): Los componentes de la interfaz deben ser operables para todos.
  → Ejemplo: Navegación por teclado, tiempo suficiente para leer contenido.

Understandable (Comprensible): La información y la operación deben ser comprensibles.
  → Ejemplo: Texto legible, mensajes de error claros, navegación predecible.

Robust (Robusto): El contenido debe ser interpretable por diferentes tecnologías de asistencia.
  → Ejemplo: HTML semántico, compatibilidad con lectores de pantalla.

📊 Niveles de conformidad WCAG:

NivelDescripciónRequisitos mínimos
A (Básico)Cumple los criterios esenciales20 criterios de éxito
AA (Intermedio)Estándar para la mayoría de sitios web50 criterios de éxito (recomendado)
AAA (Avanzado)Máximo nivel de accesibilidad70 criterios de éxito (difícil de alcanzar)

🎯 Ejemplos de criterios de éxito (nivel AA):

  • 🎨 Contraste de color: Relación de contraste de al menos 4.5:1 para texto normal
  • ⌨️ Navegación por teclado: Todas las funcionalidades deben ser accesibles desde el teclado
  • 🖼️ Texto alternativo: Todas las imágenes no decorativas deben tener alt text
  • 📝 Etiquetas de formulario: Todos los campos de formulario deben tener etiquetas claras
  • 🔍 Redimensionamiento de texto: El texto debe poder redimensionarse hasta 200% sin pérdida de funcionalidad
  • 🎬 Subtítulos: Los videos deben tener subtítulos

📚 Profundización en UI/UX

1. Leyes de UX (Jon Yablonski)

Ley de Fitts

El tiempo para alcanzar un objetivo es función de la distancia y el tamaño del objetivo.

Aplicación: Botones grandes cerca del cursor, menús en bordes de pantalla.

Ley de Hick

El tiempo de decisión aumenta con el número y complejidad de las opciones.

Aplicación: Simplificar menús, agrupar opciones similares.

Ley de Tesler

La complejidad inherente de un sistema no se puede eliminar, solo trasladar.

Aplicación: Mover complejidad al código, no a la interfaz de usuario.

Efecto estética-usabilidad

Los usuarios perciben los diseños estéticamente agradables como más usables.

Aplicación: Invertir en diseño visual mejora la percepción de usabilidad.

3. Pruebas de usabilidad: número de usuarios necesario

📊 Curva de descubrimiento de problemas (Nielsen):

• 1 usuario → encuentra ~30% de problemas
• 5 usuarios → encuentra ~85% de problemas
• 10 usuarios → encuentra ~95% de problemas
• 15+ usuarios → rendimiento decreciente

Recomendación: 5-8 usuarios por prueba de usabilidad es el punto óptimo costo-beneficio.

4. Tipos de pruebas de usabilidad

  • Moderadas en persona: Un moderador observa y guía al usuario en persona. Permite preguntas en profundidad.
  • Moderadas remotas: El moderador observa al usuario a través de videollamada. Útil para usuarios distribuidos.
  • No moderadas remotas: Los usuarios completan tareas por sí solos, grabando su pantalla y voz. Escalable, menos detalle.
  • Pruebas A/B: Comparar dos versiones del diseño con diferentes usuarios. Para decisiones basadas en datos.
  • Pruebas de guerrilla: Pruebas rápidas en lugares públicos (cafeterías, parques). Bajo costo, feedback inmediato.
  • Pruebas de árbol (Tree testing): Evaluar la arquitectura de información sin diseño visual.
  • Clasificación de tarjetas (Card sorting): Usuarios organizan contenido en categorías para definir estructura de navegación.

5. Checklist de usabilidad para tu proyecto:

___  ¿La navegación es intuitiva y consistente?
___  ¿Los botones y enlaces tienen etiquetas claras?
___  ¿Los mensajes de error son útiles y específicos?
___  ¿El sistema proporciona retroalimentación para cada acción?
___  ¿Se puede deshacer/rehacer acciones importantes?
___  ¿Los usuarios pueden completar tareas comunes en pocos clics?
___  ¿El texto es legible (tamaño, contraste, fuente)?
___  ¿El diseño es responsive (funciona en móviles)?
___  ¿Se han probado los flujos críticos con usuarios reales?
___  ¿La puntuación SUS es superior a 68?
